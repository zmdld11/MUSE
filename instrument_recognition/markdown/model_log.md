# 乐器识别模型研发日志

## 待突破基线：CNN (85%) -> ResNet (95%)

### 版本: VER1.8_MixupTimeShift
**目标**：解决 VER1.7 中由于过度对齐“纯净音轨0.1s作为音头”而在推理阶段出现的严重位移敏感与过拟合问题（导致钢琴被误判为原声吉他 GAC 不降反升）。同时落地用户提出的“自行混音做增强”的高级训练集构造思路。

**创新点 / 尝试**：
1. **时间轴循环平移 (Time-Shift Augmentation)**：之前 `data.py` 里抓取的 MedleyDB 音头强制写死在 0.1s 起点，使得模型“死记” 0.1s 位置的波形凸起就是发声。现在在 `__getitem__` 放入了 `-30% ~ +30%` 随机时间平移操作（Roll），彻底打破模型对时间的“硬对齐”依赖，使 `infer.py` 用任意时间窗口扫掠时都能游刃有余地锁定音头。
2. **动态混音增强 (Mixup Augmentation)**：完美对应用户“不依赖原数据，用纯净轨自己拼凑混合音轨”的需求。由于传统的物理合并极度消耗 I/O 和硬盘，我们在 `train.py` 中以 `alpha=0.2` 直接切入了学术界最前沿的 Mixup 机制：在每个 Batch 的内存里以一定随机比例实时融合两段音频特征图并混合 Label（如 80%吉他+20%钢琴）。这相当于让模型每步都在见识亿万种“自组装重混音频”，从而彻底治愈泛化性差和吉他/钢琴幻觉。

**预期效果**：通过这两套极具破坏力且直接治本的数据增强，Train Acc 会非常稳定地被拉低（无法再靠作弊死记硬背冲上 92%），但这会逼迫模型学到真正的乐器音色本质。

**最终模型性能评价**：
- Train Acc 如预期一般极其稳定地压在了 **87% - 88%** 之间波动，不再疯狂膨胀（说明增强抗过拟合非常成功）。
- Val Acc 稳定收敛于 **83.5% - 84%** 左右，但距离 85% 基线还差临门一脚。
- 钢琴被识别为吉他的“幻觉”，虽然缓解了一点，但是仍然存在明显干扰。这主要根源出在了 IRMAS 数据集本质上（大量混音切片单标签），当混入 MedleyDB 进行增强时依然无法根治这片“毒瘤”数据。

### 下次修改建议 (计划 VER2.0_MedleySynthetic: 数据集大洗牌突破 95%)

正如用户的洞察：“感觉 irmas 的乐器种类太少了一点，要不要改成纯正的 MedleyDB 手动产生数据集？” —— 这是一个极其伟大的、决定性的判断。IRMAS 不仅种类只有 11 个，最要命的是它是混音却只有“单标签”（比如里面有吉他、鼓、贝斯，但可能标注为：人声）。这会导致我们的分类器（CrossEntropy）永远无法达到人类的精准度。

在 VER2.0 中，彻底抛弃旧式思路，进行大范围重组：
1. **全面纯净音轨化**：彻底淘汰 IRMAS。将目光转向 MedleyDB, nsynth 或 Moisesdb 等拥有多轨分离（Stems / Tracks）的庞大干净仓库，扩大能够识别的乐器列表。
2. **手搓实时混合训练集 (Custom Mixer)**：如用户提出的方案，利用分离出来的干净高音（如 Flute）和贝斯（如 Bass），动态混音（直接相加并 Normalize），自动打上 `[1, 1, 0, ..., 0]` 的多标签（Multi-label）。
3. **架构变质 (CrossEntropy -> BCEWithLogitsLoss)**：目前的模型在做“单选题”（Softmax，加起来概率必须是 1），如果听到钢琴+贝斯，它只能极其痛苦地挑一个，如果遇到吉他扫弦和钢琴和弦（它们同时有清脆的音头），网络更是无法分辨。下一代网络必须改成 `Sigmoid` 加 `BCEWithLogits Loss` 进行“多项选择题”预测（每个乐器独立判断是否有声），这是让 84% 飞跃至 95% 以上的最核心改造。
**模型结构**：
- 输入层：1 通道 / 3 通道 Mel-spectrogram
- 主干网络：PyTorch `ResNet34` (比起 1.0 的 18 更深)
- 丢弃层：最后加入两个强力组合：`Dropout(0.6) + Linear(256) + ReLU + Dropout(0.4)`，大幅压缩拟合余地

**创新点 / 尝试**：
1. 这是基于用户提供的旧有效方案的改良：由于 85% 原分类器强行采用了高达 `0.5/0.8` 的 Dropout 率制裁了过拟合，我们也在全连接部分使用了极高的失活率。
2. 数据增强（Data Augmentation）：在 `dataset.py` 中新加了随机环境频域（`FrequencyMasking=15`）和时域（`TimeMasking=15`）裁剪，以及微小的随机高斯噪音，破坏模型死记硬背样本特征。
3. 加入 `L2 权重衰减 (weight_decay=1e-3)`。
4. 挂载了 `LR_Scheduler (ReduceLROnPlateau)`，在验证 Loss 遭遇平静期 3 轮以上时自动对折下调学习率。
5. 轮次上限打开到 50 轮探索拟合边界。

**最终模型性能评价**：
- Train Loss: 最低降至 0.01 左右，训练极其充分。
- Val Loss: 一直在 2.1 左右徘徊不能下降。
- Val Acc: 经过长时间摩擦，最高只能稳定在 60.48%。

**下次修改建议/分析**：
尽管挂载了最高强度的 Dropout 和数据增强。但 1.1 版本依然陷入了过拟合和特征不举的困境（卡死在 60%）。
这是由一个**致命失误**引起的：`ResNet34` 预加载了 ImageNet 的权重，但其实那是识别 RGB（3 通道）图像的。在我们的代码中，用 `nn.Conv2d(1, 64...)` 将它的第一层强行替换成了单通道，但这**完全清空了预训练特征**并用随机数进行了初始化。这就导致整个残差网络等于在第一层输入随机噪声，被迫在仅仅区区几千张 3 秒乐器样本上从头训练了一个千万参数的 ResNet34！

### 版本: VER1.2 (跨界微调复用术 / 剑指 90%+)
**模型结构**：
- 输入层：1 通道 Mel-spectrogram
- 主干网络：PyTorch预训练 `ResNet34`
- 修复核心：**预训练权回复**。将原来 ImageNet 第一层 Conv2D (3通道) 的权重通过取平均（`weight.sum(dim=1, keepdim=True)`）或者同等复制，巧妙地塞回我们强行魔改的、接收 1 通道频谱图的第一层小卷积内核中。让网络保留原本的“边缘、纹理特征提取能力”。

**创新点 / 尝试**：
1. 修复了残差主干 `conv1` 层由于通道削减导致预训练被撕裂的问题。
2. 保持之前的高 Dropout 和 SpecAugment 保护伞不变。

**最终模型性能评价**：
- Train Loss: 最低降至 0.008 左右
- Val Loss: 一直在 1.85 ~ 1.95 波动
- Val Acc: 最终稳定在 62.6% 左右，仍然未能突破 85% 基线。

**下次修改建议/分析**：
尽管恢复了第一层权重，但由于使用了 Min-Max 归一化破坏了频谱响应比例、未引入类别均衡采样（导致严重偏置）、全连接层依然过于臃肿带有极高 Dropout(0.6/0.4) 导致严重欠拟合，以及 Adam 收敛过快等问题综合发作，模型依旧被焊死在 60% 左右。需要对这4项进行彻底回调。

### 版本: VER1.3 (回归本质：旧版特性移植重建 / 剑指超越 85%)
**模型结构**：
- 输入层：1通道提取后使用 `.repeat(3, 1, 1)` **直接伪装复制为 3 通道图**，完美适配 ResNet34 输入要求（不修改主干的 conv1）。
- 主干网络：PyTorch预训练 `ResNet34` (不破坏任何原生结构)
- 输出层：放弃臃肿的全连接结构，利用其内部自带的全局平均池化直接接 `nn.Sequential(nn.Dropout(0.3), nn.Linear(512, 11))` 的单薄分类头。

**创新点 / 尝试**：
1. **彻底修复特征撕裂**：不改主干通道数，用真实的三通道“伪彩色图”骗过网络从而100%保留 ImageNet 提取能力。
2. **底层标准化回归**：在 `dataset.py` 中将音频处理从容易受异常值暴击的 `Min-Max` 区间缩放全面换回 `Z-Score`。
3. **样本均衡采样**：引入 `WeightedRandomSampler` 来严格按样本数倒数概率抽样，强迫模型对每个乐器“一碗水端平”。
4. **更换稳定策略**：采用带 `momentum=0.9` 的 `SGD` 来替换 `Adam`，配以 `CosineAnnealingLR` 让其更好地在长距离微调中寻找最优泛化解。

### 版本: VER1.0 (已合档)
**模型结构**：
- 输入层：1 通道 / 3 通道 Mel-spectrogram
- 主干网络：PyTorch 官方预训练的 ResNet18 特征提取器（相比前版 CNN 带深层残差连接）
- 输出层：Dropout(0.5) 避免过拟合 + 11 维全连接分类器输出。

**创新点 / 尝试**：
1. 使用深层残差结构（ResNet）代替浅层 CNN 进行多乐器分类，期望泛化能力提升。
2. 更改最后的全连接结构，增加一个 Dropout。
3. 动态配置通道及超参（`in_channels=1` / `num_classes=11`）并打包保存在 `pth` 伴随字典中，方便后续的测试代码能够实现“自适应加载不脱节”。

**最终模型性能评价**：
- Train Loss: 平均降低至 0.13 左右（但产生过拟合现象）
- Val Loss: 平均在 2.3 左右，与训练 Loss 产生显著背离
- Val Acc: 最终稳定在 53% 左右

### 版本: VER1.5_AugmentedCNN
**目标**：突破80%瓶颈期，降低推理时的幻觉与误报率，并向85%以上的基线推进。

**创新点 / 尝试**：
1. **训练中引入 SpecAugment**：在每次读取音频生成梅尔频谱图后，加入随机的时间遮蔽（Time Masking）与频率遮蔽（Frequency Masking）。这能强制模型不去强行记忆背景的垃圾片段或瞬态噪声，从而极大降低虚假阳性。
2. **Cosine Annealing 学习率调度器**：在 `train.py` 中引入 `lr_scheduler.CosineAnnealingLR` 让学习率后期进行平滑余弦退火，寻找极小值时不再剧烈震荡。
3. **增加 Dropout 与 Weight Decay**：微调了头部 Dropout，并在优化器加入 `weight_decay=1e-4`。

**说明：关于控制台输出的 LR**：
- **LR (Learning Rate, 学习率)**：这是模型在每一次“犯错”后，决定调整自身参数的“步伐大小”。
- 当 LR 很大时，模型能快速向目标靠近，但容易在目标附近反复横跳（震荡）而无法精准落入最低点；
- 当 LR 变小后（如 1.5 加入的 Cosine Annealing 余弦退火），模型的步伐会越来越细腻，从而能在大后期慢慢“滑”进误差最小的神奇点（最优解）。

**最终模型性能评价**：
- Train Loss: 停滞在 0.73 左右。
- Val Acc: 最终只爬升到约 74.5% 左右。

**问题与分析**：
- **典型的“强力正则化”导致“欠拟合”**：VER1.4 能跑到 80.8%，而加上诸多保护机制的 VER1.5 反而掉到了 74%。这是因为 CustomCNN 模型本身的总体参数量极小（仅 76k）。
- 当同时堆叠 SpecAugment（直接给数据打马赛克）、Dropout（丢弃神经元）、以及 Weight Decay（参数衰减）时，这个小网络连记住正常特征都很吃力了，更何况还要抵御马赛克干扰，所以它被这些“枷锁”限制住了发挥。

### 版本: VER1.6_WiderCNN
**目标**：解决 VER1.5 各路正则化太强导致的欠拟合问题，提升网络脑容量。

**创新点 / 尝试**：
1. **网络加宽 (容量倍增)**：将基础 CNN 的逐层通道翻倍 `(16->32 -> 32->64 -> 64->128)`。模型参数量从堪堪 76k 直接提升到了近 300k。让其拥有足够的参量空间来消化正则化带来的扰动。
2. **减弱束缚**：
    * 将 SpecAugment 的强度降维（mask 块从各2块降低为1块，屏蔽最大范围由15缩减为10，且触发几率从 50% 下降至 40%）。防止图片被割裂得连乐器都认不出来。
    * 从 `Adam` 中移除了 `weight_decay=1e-4`，彻底拉掉手刹，放缩让模型放开身心拟合。

**预期效果**：大模型结构配合中等数据增强，模型能够重现最初那种奔着 80% 甚至更高冲锋的势头，且不应该在推理中引发严重过拟合造成的幻觉。

**最终模型性能评价**：
- Train Loss: 最低降至 0.17 左右，Train Acc 飙升至 94.4% 左右。
- Val Loss: 后期约在 0.58 ~ 0.61 左右。
- Val Acc: 最终被卡在 82%~83% 之间。

**问题与分析**：
- **出现了明显的过拟合现象**：相比于上个版本的欠拟合，VER1.6（300k 参数结构）展现出了强大的吸收能力，训练集准确率一路高歌猛退过 94%。然而，验证集却在 82% 左右迟迟上不去。
- **推理幻觉检测问题**：在 `infer.py` 实际推理卡农（canon）钢琴版时，时间线出现了频繁的 `gac`（acoustic guitar / 原声吉他）误报。一方面，可能是因为预测阈值设置不够严谨；另一方面，其实就是验证集所反馈的模型**泛化能力**依然薄弱，由于 IRMAS 原声乐器样本中可能掺杂了类似击弦/扫弦特征，网络错误地“背”下了这些噪声。

### 版本: VER1.7_MixedWiderCNN
**目标**：纠正数据引入时忘记修改版本号导致污染1.6断点的问题。同时解决加上纯净音轨后再次出现的过拟合现象。

**创新点 / 尝试**：
1. **纯净音轨“音头”训练 (继承自刚才的数据集 V2)**：利用 MedleyDB 专项处理版抽出 `0.1s - 2.9s` 极短爆破音。并给该数据打上 3.0 倍的高权重强行送入抽样器（WeightedRandomSampler），让模型死记乐器本音区。
2. **回调 L2 正则约束**：在上一版 VER1.6 里，我们因为当时模型小（76k）去掉了所有的惩罚（weight_decay）。但现在模型有近 300k 的容量，且在 1.6 的那轮测试里达到了 `Train 94% / Val 82%` 和刚才错误覆盖的 `Train 92% / Val 81%` 的严重过拟合。所以在本次 1.7 中，重新在 Adam 里加回了 `weight_decay=1e-4`。
3. **加重遮挡增强强度**：将 SpecAugment 从刚才非常轻微的 1块/10格/40% 调回了 2块/12格/50% 几率。进一步防止网络死记硬背。

**预期效果**：在纯正音头训练 + 回调中高强度的双重抗过拟合手段下，把虚高的 92% Train Acc 按下来，让 Val Acc 重获新生冲击 85% 基线，并彻底杀灭推理文件里的幻觉误报。
