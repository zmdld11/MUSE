# 多标签乐器识别 — 近三年(2023-2025)研究文献综述

> 编写日期: 2026-05-03
> 目的: 调研学界在多标签/复调乐器识别领域的最新方法，寻找突破当前 85% F1 瓶颈的技术路线。

---

## 一、当前 MUSE 模型 (VER3.1) 现状分析

### 训练日志关键数据

| 指标 | 数值 |
|------|------|
| Epoch 1 Train F1 | 19.45% |
| Epoch 1 Val F1 | 33.12% |
| Epoch 200 Train F1 | 81.02% |
| Epoch 200 Val F1 | 84.07% |
| 最佳 Val F1 | ~84.85% (epoch 190) |
| Train/Val F1 差距 | Val 持续高于 Train 约 3-10% |

### 数据分析：Val > Train 不是"欠拟合"

学术界已明确验证：**Mixup 训练时，验证 Loss/F1 优于训练是正常且预期的现象**。原因：

1. **训练时标签被混合软化**：Mixup 将两个样本按 `λ*x₁ + (1-λ)*x₂` 混合，标签变成 0 到 1 之间的软标签。模型需要预测模糊的中间值（如 "70% 吉他 + 30% 钢琴"），这不是一个可以"彻底答对"的任务 → 训练 Loss 天然偏高、F1 天然偏低。

2. **正则化仅作用于训练**：Dropout、SpecAugment、随机增益等全部只在训练时启用，验证时关闭 → 验证任务更简单。

3. **度量时点差异**：训练 F1 是每个 batch 更新时的瞬时值，验证 F1 是整个 epoch 完成后评估 → 模型已经"多学了一圈"。

**结论：这不是故障，是 Mixup 训练的标准行为。** 真正的问题在于：
- 数据严重不均衡（合成器 384 vs 电贝斯 2977 = 7.75倍差距）
- 单阈值判定导致稀有类别漏检
- 模型缺乏逐类别的置信度标定

### 实际推理中的漏检问题

当前 `infer.py` 使用全局统一阈值 0.65 + 5帧平滑窗口。这对高频类别（电贝斯、钢琴、架子鼓）足够，但对低频类别（合成器、木吉他、小提琴）可能过高，导致**稀有乐器被漏检（False Negative）**。

## 二、2023-2025 年主要方法分类

### 2.1 自监督预训练方法 (SSL / Foundation Models)

#### MERT: Acoustic Music Understanding Model (ICLR 2024)

| 项目 | 内容 |
|------|------|
| 作者 | Yizhi Li 等 (HKUST, 字节跳动等) |
| 参数量 | 95M ~ 330M |
| 预训练数据 | 160,000 小时音乐 |
| 核心思想 | 双教师模型——声学教师(RVQ-VAE) + 音乐教师(CQT频谱)，MLM式掩码预训练 |
| 关键结果 | 在 14 个音乐理解任务上达 SOTA，包括乐器分类 |
| 开源 | HuggingFace: `m-a-p/MERT-v1-95M`, `m-a-p/MERT-v1-330M` |

**HamNava 多标签乐器数据集 (2025) 上的 MERT 表现：**

| 模型 | 准确率 | F1 |
|------|--------|-----|
| CNN 基线 | 82.50% | 65.81% |
| MusicHuBERT | 88.21% | 81.02% |
| **MERT** | **90.85%** | **84.98%** |
| **Music2vec** | **91.59%** | **86.06%** |

**对我们的启示**：MERT/Music2vec 用大规模预训练从原始音频直接提取特征，不需要手工设计 mel-spectrogram + MFCC。但 95M+ 参数量对 RTX 4060 8GB 可能太重，需要用小模型蒸馏或特征冻结微调。

#### Music2vec (BYOL-based, 2025)

基于 BYOL (Bootstrap Your Own Latent) 的自监督框架，在 HamNava 上甚至略超 MERT。不需要掩码重建，训练更高效。

---

### 2.2 超越 Transformer: Focal Modulation Networks (2025)

| 项目 | 内容 |
|------|------|
| 作者 | Reghunath, Rajan (Amrita Vishwa Vidyapeetham) |
| 发表 | The Journal of Supercomputing, 2025年5月 |
| 核心思想 | 用 Focal Modulation 替代 Self-Attention——不需要计算所有 token 之间的 pairwise 注意力分数，而是用层次化上下文 + 门控聚合 |
| 关键结果 | Macro F1: 0.58, Micro F1: 0.66 (IRMAS 数据集)，比 ViT/Swin-T/CCT 高 10-16% |

**Focal Modulation 的优势**：
- 计算复杂度 O(N) vs 自注意力 O(N²)
- 不需要位置编码
- 对中小数据集更友好（不像 Transformer 需要大量数据）

**对我们的启示**：当前 VER3.1 的 Transformer 只有 33 个时间步，序列很短，自注意力的优势可能没有完全发挥。Focal Modulation 可能是更适合的选择。

---

### 2.3 紧凑卷积 Transformer (CCT, 2024)

| 项目 | 内容 |
|------|------|
| 作者 | Lekshmi C. R., Rajeev Rajan |
| 发表 | ICCES 2024 |
| 核心思想 | 用卷积 Tokenizer 替代 ViT 的线性 Patch Embedding，使 Transformer 更适合小数据集 |
| 适用场景 | 数据量不够预训练 ViT 时的替代方案 |

**与我们的关联**：CCT 的设计思路和 VER3.1 有相似之处（CNN backbone + Transformer），但 CCT 用了卷积 Patch Embedding 直接 tokenize 频谱图，而我们用 CNN backbone 逐步降维。可以借鉴 Tokenizer 设计。

### 2.4 多特征融合方法

#### 频谱图 + Modgd-gram 融合 (CSSP 2023)

| 项目 | 内容 |
|------|------|
| 作者 | Lekshmi C. R., Rajeev Rajan |
| 核心思想 | Mel-spectrogram (幅度) + Modified Group Delay Function (相位) 双支路 CNN 后期融合 |
| 增强手段 | WaveGAN 生成合成多乐器训练数据 |
| 关键结果 | Micro F1: **0.69**, Macro F1: **0.62** (IRMAS)，超过 Transformer 集成方法 |

**对我们的启示**：当前只用了 mel-spectrogram 的幅度信息 (AmplitudeToDB) + MFCC，完全丢弃了相位信息。Modgd-gram（改进的群延迟函数）能捕获相位突变，对音头/起始瞬态检测非常有效——而这正是 VER3.0 计划中推迟的"音头特征"！

#### 多输入 DWT-CNN (2024)

| 项目 | 内容 |
|------|------|
| 作者 | Dash, Solanki, Chakraborty |
| 发表 | CSSP 2024 |
| 核心思想 | 离散小波变换(DWT) + CNN，用粒子群优化(PSO)做特征选择 |
| 关键结果 | Micro F1: 0.695, Macro F1: 0.631 (IRMAS) |

### 2.5 演奏技巧检测相关方法 (可迁移)

#### 多尺度网络 + 自注意力 (ICASSP 2023)

| 项目 | 内容 |
|------|------|
| 作者 | Dichucheng Li 等 |
| 核心思想 | 多尺度 CNN 提取不同时间粒度的特征，在最粗尺度上施加自注意力 |
| 关键创新 | 帧级别多标签分类 + 多任务学习 (音高+起始+技巧) |

#### MERTech (ICASSP 2024)

| 项目 | 内容 |
|------|------|
| 作者 | Dichucheng Li 等 |
| 核心思想 | MERT 预训练 + 多任务微调 (音高检测 + 起始检测作为辅助任务) |
| 后处理 | 结合起始确认 (onset confirmation) 做事件级别预测，消除孤立误检 |

**对我们的启示**：多任务学习（同时预测音高起点和乐器类别）可以显著减少幻觉和漏检——如果模型知道"这里没有音符开始"，就不会误报一个乐器。

### 2.6 数据增强与损失函数改进

#### LogicMix (2024)

多标签场景下的 Mixup 改进：标准 Mixup 对 multi-hot 标签做线性插值会产生不合理的中间值。LogicMix 用**逻辑 OR** 替代线性插值来混合多标签目标。

#### 类别自适应阈值 (Class-Adaptive Thresholding)

取代全局单阈值判定（如当前 0.65），为每个类别学习最优判定阈值。步骤：
1. 在验证集上计算每个类别的 precision-recall 曲线
2. 找到使每个类别 F1 最大化的独立阈值
3. 推理时对各类别使用不同阈值

**这是解决"稀有类漏检、常见类幻觉"的最直接手段。**

## 三、关键方法对比总结

| 方法 | 参数量 | 数据需求 | 特点 | 适用性 |
|------|--------|----------|------|--------|
| **MERT 微调** | 95M+ | 需要预训练权重 | SOTA, 通用性强 | 重量大, 8GB VRAM 边界 |
| **Focal Modulation** | ~2-5M | 中等 | 替代自注意力, 效率高 | ⭐ 非常适合我们的规模 |
| **CCT** | ~1-3M | 较少 | 卷积 Transformer | ⭐ 与当前架构相近 |
| **Modgd-gram 融合** | ~0.5-1M | 中等 | 相位+幅度双特征 | ⭐ 可加到现有模型 |
| **类别自适应阈值** | 0 | 无 | 后处理改进 | ⭐ 立即可用 |
| **多任务学习** | +少量 | 需要标注 | 音高+起始辅助 | 需要数据支持 |
| **LogicMix** | 0 | 无 | 改进 Mixup | ⭐ 立即可用 |

## 四、针对 MUSE VER3.1 的改进建议路线图

### 短期 (立即可做，不改模型结构)

1. **类别自适应阈值** (Class-Adaptive Thresholding)
   - 在验证集上为每个类别独立计算最优 F1 阈值
   - 解决合成器(稀有)漏检 vs 电贝斯(高频)误检的矛盾
   - 零成本，直接改 infer.py

2. **LogicMix 替代标准 Mixup**
   - 用逻辑 OR 替代线性插值混合多标签
   - 在 train.py 中修改 mixup 的标签混合策略

3. **数据再平衡**
   - 当前数据分布：合成器 384 ↔ 电贝斯 2977（7.75倍差距）
   - 在 build_mixed_dataset.py 中进一步加大稀有类采样权重
   - 目标：最稀有类至少占 8%

### 中期 (需小幅改模型)

4. **Modgd-gram 特征融合**
   - 在 dataset.py 中增加相位特征（Modified Group Delay）作为第 2 通道
   - CNN 骨干从单通道改为双通道输入
   - 可显著改善音头检测和瞬态建模

5. **Focal Modulation 替代 Transformer**
   - 替换 `self.transformer` 为 Focal Modulation 模块
   - O(N) 复杂度, 更适合短序列
   - 论文显示优于同参数量的自注意力

### 长期 (需较大改动)

6. **MERT 蒸馏 / 冻结特征**
   - 用 MERT-v0 (95M) 作为特征提取器，冻结前 N 层
   - 在其上加轻量分类头
   - 或蒸馏 MERT 到 3-5M 的小模型
