# 记谱规则 v1

2026-08-22 研讨定案（用户拍板项：入谱线过滤 / 结构化清洗 / 量化双模式 / 单乐器谱首发）。
数据依据：虚無の先（05_kyomu_vocal）ia-amt default 全乐队输出，1887 音符 / 9 轨 /
264s / bpm 80.7。落地代码：`src/multi_instrument.py`（数据层部分）。

## 0. 结论速览

| 议题 | 决策 |
|---|---|
| 小轨处理 | 数据层永不删轨；记谱层默认只收「音符数 ≥ 16 且活跃覆盖 ≥ 5%」 |
| 跨族改判 | 不做（无逐音置信度、velocity 恒 100，无排序依据） |
| 同音高重叠 | 截断前音保后音音头（唯一数据层硬规则） |
| 同音高间隙合并 | **不做**——40ms 合并规则已被实测证伪（见 §3.2），判定延后到量化后 |
| 超长音 | 不截断，交给连音线链 |
| 超短音 | 不删，由量化层吸收 |
| 量化 | 双模式：量化（16 分网格 + 分段偏移搜索 + 三连音候选）与忠实（不量化）可切换 |
| 谱种 | 记谱层输入 = 轨道子集；v1 先做单乐器谱（吉他五线谱+TAB / 钢琴大谱表） |

|---|---:|---:|---:|---:|---:|---|
| distorted_guitar | 617 | 73.6% | 608 | 13 | 5 | ✓ |
| acoustic_guitar | 388 | 47.1% | 346 | 7 | 8 | ✓ |

| electric_piano | 77 | 27.5% | 98 | 5 | 1 | ✓ |
| electric_guitar_clean | 23 | 9.2% | 24 | 0 | 0 | ✓ |
| strings | 13 | 5.8% | 17 | 0 | 0 | ✗（疑似误判） |
| sax | 5 | 0.6% | 1.5 | 0 | 0 | ✗（疑似误判） |

*活跃覆盖 = 该轨音符区间并集 / 全曲时长。

关键分布特征：

- **时值阶梯聚集**：全曲时值十分位 0.187 / 0.35 / 0.70 / 1.45s ≈ 16 分 / 8 分 /
  4 分 / 2 分（@80.7bpm）。Semi-CRF 区间输出天然贴近音乐时值 → 时值量化友好。
- **音头连续分布**：对齐 t=0 锚定 16 分网格 ±50ms 命中率仅 54.4%（±30ms 34.2%）→
  onset 量化必须分段偏移搜索（复用 `quantize_timing.py`），不能全局硬对齐。
- **无力度/置信度信号**：velocity 恒 100、confidence 恒 1.0 → 一切基于力度或置信度
  的清洗规则不可用，只能靠时序/音高先验。

## 2. 轨道准入（入谱线）

- **数据层**（notes.json / .mid / 前端卷帘 / 播放）**永不删轨**。
- **记谱层默认集合**：`note_count ≥ 16 且 active_coverage ≥ 5%`
  （代码常量 `SCORE_MIN_NOTES` / `SCORE_MIN_COVERAGE`）。
- notes.json 每轨新增字段：`note_count`、`active_coverage`、`score_worthy`、
  `cleanup`（截断/丢弃计数），前端据此展示默认入谱集合。
- 不做跨族改判：把疑似误判的音塞进干净轨道等于注脏水。同族合并（如
  electric_guitar_clean 并入吉他组）留到前端「入谱勾选」之后。
- 用户可手动覆盖：前端逐轨勾选强制入谱/出谱（M4 乐谱页交互）。

## 3. 数据层时值清洗

### 3.1 唯一硬规则：同音高重叠截断

后音 onset 早于前音 offset 时截断前音（保住后音音头）；截断后短于 23ms 的残段
（重复音头）丢弃并回溯。虚無の先：26 处截断、0 丢弃，清洗后不变量「无同音高
重叠」校验通过。必要性：重叠区间无法画进单声部谱面。

### 3.2 40ms 间隙合并规则的证伪（重要教训）

原设计「同音高间隙 < 40ms 合并（对抗 ia-amt H7 过度分段）」，离线验证时发现
**大错**：该规则会合并 701/1887 个音（37%），把贝斯/吉他的真实节奏线摧毁。

证据（虚無の先 electric_bass，pitch 33 连续段）：

```
a=(18.896,19.239,dur=0.343) b=(19.267,19.610,dur=0.343) gap=0.028 onset间距=0.371
a=(19.267,19.610,dur=0.343) b=(19.637,19.982,dur=0.345) gap=0.026 onset间距=0.369
```

onset 间距 0.371s = 精确的八分音符（0.372s），时值填满间距 92%——这是行走贝斯
的八分脉冲，不是接缝。全曲 <40ms 邻接对的 gap 分布高度集中（p25–p75 =
0.021–0.025s），说明 **~23ms 间隙是 ia-amt 对同音高再触发的系统性 release 约定**，
而非随机分段伪影；邻接对的 onset 间距分布峰值精确落在 8 分（0.37）/ 4 分（0.72）/
2 分（1.47）网格上。

**修正后的规则**：数据层对正间隙一律不合并。接缝 vs 再触发的判定延后到量化后
（记谱层）：量化后 onset 落在网格上 = 再触发（保留重复音），不在网格上且间隙
极小 = 接缝（合并）。H7 的过度分段问题应按此口径重新评估。

### 3.3 超长音与超短音

- 超长音不截断：实测 36 个 >4s 音大多真实（11s 失真吉他持续音、255.5s 处 8.5s
  终止和弦），记谱层用连音线链表达。物理合理性上限（拨奏衰减等）待多曲数据
  再定，v1 不设。
- 超短音不删：全曲仅 34 个 <0.1s，音头位置本身是信息；由量化层吸收成最小时值。

### 3.4 节奏简化器（2026-08-23 增补，治"谱脏"）

确诊数据（虚無の先）：75.1% 事件带连音线、62% 链不跨小节、85.3% 可缩单值、
56% 链尾悬空；原始分段健康（99.4% 同音高间隙在网格上 = 真实再触发）。
脏在记谱层时值路径，三步修复（量化后、分解前）：

1. **同时性聚类**：原始 onset 距簇首 <40ms 的**不同音高**归到最早音头
   （扫弦 stagger 不摊成分解琶音）；同音高绝不并入（A1 教训）。
2. **时值再分配**（onset 可靠、offset 不可靠 → 时值由语境决定）：
   ratio = 原始时值 / 到下一同音高 onset 间隙——
   - ratio ≥ 0.85（连奏）：填满，≤ min(gap, 一小节) 的最干净片段组合；
   - ratio < 0.5（断奏）：≤ 原始时值的最大标准单值，剩余交休止符；
   - 中间态：向下取最近标准值（拖尾衰减，宁短勿拖）。
   持续音封顶一小节（用户拍板）。量化后离网格的同音高接缝（<40ms）
   并入前音（§3.2 遗留判定，实测仅个位数）。
3. **分解 v2**：小节内永远单值（允许附点跨拍）；只跨小节才切且 ≤2 片；
   仅当起点到小节线距离为标准值时才允许跨线（保持 tie 连续性）。

守护：小节末尾余量不足 16 分的 onset 前吸附到小节线（防 music21 溢出
漂移）。实测：连音线 75.1%→1.2%，小节内连音 867→0，4+ 片段 491→0。

**碎休止符治理（2026-08-23 夜增补）**：①量化位置网格 1/48→1/12（16 分
∪ 8 分三连音并集；1/48 会让 onset 落到 64 分位置）；②时值语境过滤——
当前与下一同 pitch 音头都在二分网格时禁三连音时值；③休止分解用最少片
数 DP（词表去 1/12），孤立 1/12 间隙延长前音吸收（不移动后续 onset，
防连奏级联）。实测：64 分 435+→0、32 分休止 466→3。

## 4. 量化双模式

- **量化模式**：onset 对齐 16 分网格；复用 `quantize_timing.py` 的分段偏移搜索 +
  三连音候选网格；残余误差超阈值（> 网格的 1/4）的段落不硬拉、打低置信标记。
- **忠实模式**：不做分段网格量化，onset/时值取原始值，以 1/48 四分音符网格
  （≈15.5ms@80bpm）表达，时值与休止分解为合法时值链（music21 导出约束，
  原计划的 1/96 因 MusicXML 单层 tuplet 限制不可行）。谱面会呈现非标准时值与
  碎休止——这正是忠实模式的语义。
- 两种都出（`MUSE_NOTATION_MODE=quantized|faithful|both`，默认 both），
  用户切换（前端设置项）。
- 依据：§1 的时值阶梯聚集（量化可行的下界）与音头连续分布（必须分段搜索的
  上界约束）。
- BPM 口径：记谱层内置网格命中率健康度（kyomu 实测 100%，bpm 80.7 验证通过）；
  命中率 <40% 时告警提示 bpm 失准。

## 5. 谱种与轨道子集

记谱层的输入定义为**轨道子集**（track subset），不默认吃全部轨道：

| 谱种 | 内容 | 优先级 |
|---|---|---|
| 单乐器谱 | 吉他 = 五线谱 + TAB；钢琴 = 大谱表；其余单五线谱 | **v1 首发** |
| 总谱 | 过准入线的轨全上，按 鼓→贝斯→吉他组→键盘→主旋律 排序 | v2 |
| 自选组合谱 | 前端勾选的任意子集 | v2 |

- 声部/排版问题最小的单乐器谱先落地，最快能和参考谱（東の空 GP8 等）对比验收。
- 低覆盖轨被用户强制入谱时，谱面会出现大量多小节休止（排版规则见 §7）。
- **和弦记号（T1，2026-08-23 增补）**：量化谱首谱表每小节起点写
  MusicXML `<harmony>`（和弦段来自 harmony_prior 和弦跟踪，N.C. 不写）；
  notation.json 顶层 `harmony_track` + 事件级 `harmony_role`
  （chord_tone/diatonic/chromatic，chromatic=离群只标记不修正）。

## 6. NotationEvent / NotationScore schema 草案（阶段 19 实现）

```
NotationEvent {
  track_ref: int                  # 指向 NotationScore.tracks[i]
  onset_sec / offset_sec: float   # 原始时间（忠实口径留存）
  bar: int, beat_in_bar: float    # 量化后位置（量化口径）
  notated_onset: Fraction         # 以四分音符为单位的小节内位置
  notated_duration: Fraction      # 量化时值（含附点）
  tie: null | "start" | "continue" | "stop"
  voice: int                      # 声部号（1=干向上，2=干向下，…）
  chord_id: null | int            # 同轨同时发声部组和弦
  pitch: int, accidental: null | "sharp" | "flat" | "natural"
  grace: bool = false
  quant_confidence: float         # 量化残差置信（低置信段标记）
}
NotationScore {
  bpm, time_signature, key, tracks[]: {instrument_class, staff_layout,
  program, is_drum, clef, events[]}
}
```

- schema 是管线（Python）与前端乐谱页（OSMD 渲染 MusicXML）之间的中间表示；
  落盘格式仍是 MusicXML（MuseScore CLI / music21 双路已存在）。
- 三个时值语义分离（沿 task_plan 路线 A 结论）：raw note-off / pedal-aware
  sounding / notated duration + pedal marking。多乐器线 v1 无踏板。

## 7. 开放问题清单

1. 拍号与变速：当前恒 4/4 恒 BPM；3/4 vs 6/8 判别、rubato/变速段，v1 不管。
2. 声部划分扩展：`voice_assign.py` 只认钢琴；distorted_guitar 617 音符混和弦
   与单音主线，需按音高中位数/音头密度扩展到吉他/贝斯族。
3. 鼓谱：drums 类 → GM 鼓组音高 → 打击谱声部映射表未写（gleitz 音色也缺鼓组，
   前端暂用 synth_drum 兜底）。
4. 调号与等音拼写：`key_estimate.py` 有雏形；升/降号选择跟调号走，未接多乐器线。
5. 低覆盖轨强制入谱的多小节休止排版规则。
6. melody 类音色：taxonomy 代表音色 65（中音萨克斯），前端显示按文件名映射成
   人声旋律，MIDI 试听音色是否换成 voice 类（52/53）待定。
7. 接缝 vs 再触发的量化后判定算法（§3.2 遗留）。
8. H7 过度分段按新口径（量化后非网格 onset）重新评估。
