# MUSE 项目进度

> **汇报日期：** 2026年7月27日
> **项目全称：** Music Unmixing & Score Extraction System (MUSE)
> **项目目标：** 将任意音频自动转化为可读乐谱的完整工具链

---

## 一、项目概述

### 1.1 项目组成模块

- 乐器识别模块
- 音轨分离模块
- 乐谱生成模块
- 前端交互模块

### 1.2 项目目标

当前目标（只分离生成demucs提供的乐器）：

```
音频输入 → 音轨分离 -（提炼出bass、guitar、piano、drum、人声五个音轨）→ 乐谱生成 → 输出乐谱
```

远期目标（自动识别并分离音轨，生成乐谱）：

```
音频输入 → 乐器识别 -（识别出乐器种类）→ 音轨分离 -（按照识别出的乐器分离）→ 乐谱生成 → 前端交互 → 输出对应乐器乐谱
```

**硬件环境：** Intel i9-14900HX + NVIDIA RTX 4060 Laptop 8GB + 32GB RAM（本机）

## 二、各模块进度详述

### 2.1 乐器识别（✅ 已完成）

**目标功能：** 识别音频中任意时刻出现的乐器，输出时间轴概率热力图。

**当前版本：** VER4.0_BinaryEnsemble

**技术方案：**

| 组件 | 技术 |
|------|------|
| 输入 | 22050 Hz 采样，3s 音频片段 |
| 特征提取 | Mel 频谱 + MFCC + ModGD 相位特征 |
| 模型架构 | CNN Encoder → Transformer → 多标签分类 |
| 输出 | 10 类乐器概率（时间 × 乐器热力图） |
| 训练框架 | PyTorch + CUDA |

**支持的 10 类乐器：** acoustic guitar, cello, drum set, electric bass, electric guitar, flute, piano, singer, synthesizer, violin

**版本演进（共 12 个版本）：**

| 版本 | 关键改进 |
|------|---------|
| VER1.4_CustomCNN | 初始 CNN 模型 |
| VER1.6_WiderCNN | 加宽卷积核 |
| VER1.7_MixedWiderCNN | 混合卷积核尺寸 |
| VER1.8_MixupTimeShift | mixup + 时间偏移数据增强 |
| VER2.0_SyntheticMultiLabel | 合成多标签训练数据 |
| VER2.2_ClassBalanceCheck | 类别平衡检查 |
| VER2.3_StrictMetric | 严格评估指标 |
| VER3.1_TransformerFreqProj | Transformer + 频率投影 |
| VER3.2_AdaptiveThreshold | 自适应检测阈值 |
| VER3.3_PitchStructured | 音高结构化特征 |
| VER3.4_ModgdPhase | ModGD 相位特征 |
| VER4.0_BinaryEnsemble | 二值化集成模型（最终版） |

**训练数据：** 初期使用 IRMAS-TrainingData（混轨数据集），后换为 MedleyDB（分轨数据集，MAX_STEMS_PER_CLASS=10）；数据增强包括 mixup、time shift、pitch shift。

**技术难点与解决：**
- 多标签分类的类别不平衡 → 合成多标签数据 + 严格评估指标
- 单模型预测不稳定 → 二值化集成模型（BinaryEnsemble）
- 特征区分度不足 → ModGD 相位特征 + Transformer 频率投影

### 2.2 音轨分离（训练失败 ）

**目标功能：** 将混合音频分离为独立乐器音轨（bass / drums / vocals / guitar / piano）。

**当前方案：** 使用预训练模型 `htdemucs_6s`（Hybrid Transformer Demucs）进行推理，直接提供 5 轨分离输出。

**自训练尝试（三个版本均未成功）：**

| 版本 | 架构 | 状态 |
|------|------|------|
| VER1.0_LightweightUMX | 频域 UMX + BLSTM mask | SDR 负值，不收敛 |
| VER2.0_UNet | 频域 U-Net + complex mask | SDR 负值，不收敛 |
| VER3.0_DemucsLM | 时域 Demucs + LSTM bottleneck | SDR 负值，不收敛 |

**训练数据：** MedleyDB 吉他音轨 + 合成混合音频；moisesdb_v0.1 补充数据。

**技术难点：**
- 自训练吉他分离模型 SDR 始终为负值，模型无法收敛
- 后来发现 htdemucs_6s 本身就支持钢琴和吉他分离（README 没有明确标注，查阅论文后才发现）
- 因此当前采用预训练模型作为推理后端，自训练暂时搁置

**训练环境：** AutoDL 云端 GPU + 本机 RTX 4060，使用 `demucs_format` 数据格式。

### 2.3 乐谱生成（进行中）

**目标功能：** 将分离后的音轨音频转换为专业五线谱（含谱号、时值、调号、临时变音记号、拍号、小节线、终止线、力度标记、速度术语、演奏法记号等），对吉他音轨额外生成六线谱。

**当前版本：** VER2.0_Bootstrap（分支 `se/ver3.1`）

#### 当前五层管线架构

```
Layer 0: 预处理      → BPM 检测 (librosa) + 音轨分离 (htdemucs_6s)
Layer 2: 转录模型    → basic-pitch Onsets-and-Frames (onset/frame 概率图)
Layer 3: 帧级后处理  → HMM 平滑 + 自适应阈值 + 连通域标注 + onset 验证
Layer 4: 音符级后处理 → onset 精修 (spectral flux) + 谐波过滤 + 和弦归组 + 调性过滤
Layer 5: 乐谱组装    → 声部分配 + MIDI 写入 + MuseScore CLI → MusicXML
```

#### 关键模块清单（共 13 个模块）

| 模块 | 功能 | 核心技术 |
|------|------|---------|
| `bpm_detect.py` | BPM 检测 | librosa.beat.beat_track |
| `source_separate.py` | 音轨分离 | htdemucs_6s Python API |
| `transcriber.py` | 转录模型 | basic-pitch 原始 onset/frame probs |
| `frame_post.py` | 帧级后处理 | HMM Forward-Backward + 自适应阈值 + 连通域 (scipy) |
| `note_post.py` | 音符级后处理 | Spectral Flux onset 精修 + 谐波过滤 + 和弦归组 + 调性过滤 |
| `voice_assign.py` | 声部分配 | 音高中位数分割 |
| `score_assemble.py` | 乐谱组装 | pretty_midi + music21 Stream |
| `export_score.py` | MusicXML 导出 | music21 MIDI→XML |
| `pipeline.py` | 主流程编排 | 5 层串联 |
| `key_estimate.py` | 调号推算 | Krumhansl-Schmuckler 算法 24 调相关 |
| `guitar_tab.py` | 吉他排指 | DP 最短路径（22 品标准调弦） |
| `chord_detect.py` | 和弦识别 | madmom CNN+CRF（已降级） |
| `quantize_timing.py` | 节拍量化 | 16 分 + 8 分三连音双网格（已禁用） |

#### 训练管线模块

| 模块 | 功能 |
|------|------|
| `train/model.py` | Onsets-and-Frames PyTorch 实现（HarmonicStack + CNN + LSTM + 双头） |
| `train/render_midi.py` | MIDI → FluidSynth 钢琴音频渲染 |
| `train/dataset.py` | GiantMIDI-Piano 数据集加载 + SHA256 磁盘缓存 |
| `train/dtw_align.py` | DTW 对齐器（Sakoe-Chiba band，E-step） |
| `train/em_train.py` | EM 训练循环（Bootstrap → E-step → M-step） |

**训练指标（2000 首，23 epochs，FluidSynth 渲染）：**

| 指标 | 数值 | 说明 |
|------|------|------|
| frame_acc | 99.6% | 帧级音高检测准确率 |
| onset_f1 | 0.853 | 音符起点检测 F1 |
| val_loss | 0.0134 | 验证集损失 |
| 模型大小 | 4.1 MB | VER2.0_Bootstrap.pth |

#### Canon 测试结果（Pachelbel Canon in D — George Winston 钢琴版）

| 指标 | 数值 |
|------|------|
| BPM | 73.9 |
| 连通域候选音符数 | 2094 |
| 经 onset 验证后 | ~1200 |
| 经谐波过滤后 | ~1100 |
| 最终输出 | 1129 notes, 98 小节 |

**听感评价：** 慢段基本准确，中段节奏偶有抖动，快段部分音符漏检且节奏不齐。

#### 当前存在的技术困难

1. **帧率瓶颈（根本限制）：** basic-pitch 帧率仅 86Hz → onset 检测精度 ±23ms；快段 16 分音符 @73.9BPM ≈ 203ms，onset 误差达 ±11%，导致节奏错乱
2. **无 offset 检测头：** basic-pitch 不直接检测音符结束，仅靠 frame_prob 下降判断，踏板混响导致 offset 偏晚、音符过长
3. **无节拍意识：** 逐帧预测输出绝对时间，不知道"现在是第几拍"；尝试过节拍量化但因 onset 误差超过网格间隔而回退
4. **自训练模型泛化差：** Fluidsynth 合成数据训练的模型（frame_acc=99.6%）在真实录音上仅输出 ~385 音符 vs basic-pitch 的 5700+，需 NoteEM 的 EM 迭代做域适应
5. **声部分离粗糙：** 仅用音高中位数分割上下声部，无真正的多声部跟踪
6. **高音区偶被吞：** 高音 onset threshold 相对偏高，振幅天然低的高音容易被误杀
